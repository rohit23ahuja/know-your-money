
Build a cross-platform expense management application called SpendSense targeted at Indian users who have bank accounts or credit cards.
The application should have an Android mobile app and a desktop app. The backend should be built in Java using Spring Boot and Maven. The mobile frontend should be built in React Native targeting Android. The desktop frontend should be built in React with Electron. The backend exposes a REST API that both the mobile and desktop frontends consume.
The core purpose of the app is to automatically read and parse financial transactions from two sources: incoming bank SMS messages on Android, and uploaded bank account statements in PDF or Excel format. Once transactions are read, the app categorizes them into meaningful spending categories like food, transport, shopping, travel, and so on. Users can also define their own custom rules to control how transactions get categorized.
The app should display spending reports and analytics so users can understand where their money is going, broken down by category, merchant, time period, and bank account.
A key feature of the app is an AI-powered conversational interface where users can ask questions about their expenses in plain English, such as how much they spent on Swiggy this month or what their biggest expense category was last quarter. This AI must run entirely on-device using a lightweight quantized language model so that no user data ever leaves the device. The entire application must work offline with no cloud dependency and no telemetry.
The application should support reading SMS from major Indian banks including SBI, HDFC, ICICI, Axis, and Kotak. It should also support importing bank statements from these same banks in both PDF and Excel formats. All amounts should be displayed in Indian Rupee format and dates in the Indian convention.
The tech stack is Java 17 and Spring Boot 3 with Maven for the backend, React Native for the Android app, React with Electron for the desktop app, SQLite for the database, Apache PDFBox for PDF parsing, Apache POI for Excel parsing, and llama.cpp Java bindings with a quantized Phi-3 Mini GGUF model for the local AI.
